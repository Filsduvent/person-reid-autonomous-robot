# MGN-v2 operational record contract

The common commands remain `python scripts/train.py --config configs/lodo/mgn_lodo_v2/mgn_lodo-<n>_seed42.yaml` and `python scripts/evaluate.py --config <pinned-evaluation-request.yaml>`. These are interface descriptions, not launch approval. The current presets stop before CUDA/data/output without qualification and an operator declaration. No separate trainer is introduced.

`MGN_LODO_ADMISSION_RECEIPT` selects an actual-UID-owned private regular0600 JSON record. `validate_training_admission` and the direct common-trainer path both enforce it. Its exact schema is defined in `mgn_lodo_operational.py`: schema/version/type/training action and genuine approval reference; canonical project/config path, raw and effective config hashes; actual release commit; qualification path/hash and full single GPU UUID. Environment Booleans or YAML fields cannot substitute for this record.

The private qualification record must have schema1/status`MGN_LODO_FOLD_QUALIFIED`, fold/config digest, actual release, source SHA256 membership snapshot, preflight digest, exact environment/UUID, and the three tested capabilities (fresh FP32 tensors, completed-epoch rollback, terminal no-op). It also includes nonempty preserved evidence file hashes and `recovery_scope={boundary_evidence: bounded_fixture,equivalence_review_reference: <actual review reference>}`. No broad recovery guarantee is inferred. Runtime code and versioned config bytes/modes/membership must equal their actual Git commit, even when unrelated dirty documents remain. The current Phase20 creates no such qualification or approval record.

Source/target inventory and artifact checks remain read-only before launch; after admitted launch, the common run records its operational scope/config/command and actual CUDA evidence. Numerical evidence distinguishes float32 tensors/AMP-disabled operation, convolution TF32 permission, actual compute capability and potential hardware TF32 support; no actual kernel arithmetic measurement or full-FP32 guarantee is claimed. The old v1 gate and its old UUID/namespace rules remain unchanged.

`MGN_LODO_EVALUATION_RECEIPT` is separate: held-out versus supplementary-reference action, exact canonical request/raw/effective hashes, exact checkpoint SHA, reviewed committed evaluation release/source bytes, environment, GPU UUID and real approval reference. Training authority never authorizes target evaluation. The result stores this scope and code identity, terminal/target metadata and actual GPU evidence. No request overrides via generic CLI options are allowed.

Held-out version2 requests use `mode:lodo_held_out`, `version:2`, architecture mgn, exact fold/target, completed terminal SHA, config/map/data digests and source C, synthetic flag, device, fresh versioned output and zero workers/batch32. The public route enforces separate resource/action admission before terminal/model/target execution. Synthetic CPU unit fixtures are explicitly test-only/non-authoritative; they are not a production CPU fallback.

Supplementary requests use `mode:mgn_single_source_reference`, `version:1`, one of12 off-diagonal pairs, original registry path/hash, original selected-best checkpoint path/hash, target config raw/effective hashes and exact target partition/list hashes, explicit no-flip, CUDA and fresh output. `no_flip_reference_plan.yaml` contains12 read-only prepared candidates using the four unchanged source checkpoints. It is not executed or approved as a benchmark campaign. Only the versioned adapter changes the evaluation identity; ordinary standalone/cross-domain source-ownership guards remain intact.

Comparisons require all3 compatible, unambiguous source references, exact partition/filter/shared retrieval-code evidence and no target BN adaptation. Their mean is primary. Target-ranked best-by-mAP and per-metric envelopes are labelled retrospective oracles, never source/checkpoint selection. Original120-epoch/source-test-selected training and new85,200-update/terminal selection remain explicit. A missing reference yields an incomplete comparison with no mean or oracle substitution.

Publication and operational receipts are local audit controls, not independent authentication/institutional approval. Same-UID modification is not a security boundary; code/data/hash checks and explicit operator scope prevent accidental drift. Future Phase21/22/23 records must be generated from observed evidence and genuine approvals, not from example strings or synthetic unit-test fixtures.
